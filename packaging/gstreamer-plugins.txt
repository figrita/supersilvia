# The GStreamer the macOS bundle and the Windows folder carry: every element supersilvia makes,
# by name in src/ or inside a pipeline string there, the demuxers, parsers and decoders
# decodebin reaches for the files nodes::Accepts lets in, and the device providers a menu
# lists, each beside the plugin it is in. packaging/macos/build-app.sh and
# packaging/windows/build.sh read it, carry each plugin named here for their machine, and
# follow the libraries those plugins link. A plugin no row names is not carried.
#
# One row per feature:  <feature> <plugin> [machines]
#
#   feature   an element or a device provider, as gst-inspect-1.0 names it; `*` carries the
#             plugin for what it registers besides elements
#   plugin    the plugin's name, as gst-inspect-1.0 says it: gst<plugin>.dll on Windows,
#             libgst<plugin>.dylib on macOS
#   machines  macos, windows or both, comma-separated; every machine where it is left out
#
# The plugin is written here rather than looked up because a hardware codec's elements are
# registered only on a machine with that hardware, which the machine building the package
# need not be. A row is the same element `--check` asks after: platform::check::GROUPS and
# platform::video::CODECS for that machine, so an element added there is added here. NDI's
# elements are compiled into the binary (video::ndi), and are no plugin's.
